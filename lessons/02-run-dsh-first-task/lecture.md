# 02-run-dsh-first-task 讲义

## 目标

- 安装并启动官方 dsh（`npx @deepseek-ai/dsh web`）。
- 跑通第一个真实任务，理解「输入 → 思考 → 工具 → 输出」的完整回合。
- 学会在 Web UI 里找到轨迹、切换会话、查看 token 消耗。
- 认识 `headless` 形态，为自动化铺路。

## 1. 安装与启动

dsh 通过 npm 分发，一条命令即可启动（需要 Node.js 22+）：

```bash
npx @deepseek-ai/dsh web
```

首次运行会下载包并初始化 `web` profile，默认地址 `http://127.0.0.1:3080`。

本课的 `code/start.sh` 做了三件事：检查 Node.js、提醒设置 `DEEPSEEK_API_KEY`、启动 Web UI。

> 注意：不设置 API Key 也能打开界面，但发任务会失败。dsh 还支持 `DEEPSEEK_BASE_URL` 指向其他 OpenAI 兼容服务。

## 2. 第一个任务

建议从「环境探测」类任务开始，因为它能立刻展示工具调用：

```text
查看当前目录，列出里面有哪些文件，并告诉我每个文件的用途。
```

你会看到 agent 并不是一次答完，而是：

1. 读当前目录（工具调用）；
2. 可能逐个读文件（更多工具调用）；
3. 汇总成一段回答。

这就是一个 **step**：一次模型请求 + 它触发的工具执行。多个 step 组成一个 **turn**（一次用户输入到最终回答的完整回合）。

## 3. 读懂轨迹页

Web UI 的轨迹（trace）是学习 harness 最好的教具。重点看四样东西：

| 看什么 | 说明 |
| --- | --- |
| Turn / Step | 回合与步骤的分界，判断模型「想了几轮」 |
| 工具调用卡片 | 参数、结果、是否成功，看模型是否按预期行动 |
| 消息来源 | 哪些是你发的，哪些是模型注入的上下文（如文件变更通知） |
| Token 统计 | prompt/completion 消耗，培养成本直觉 |

第 03 课会把这些字段和底层 session 日志对应起来。

## 4. headless 形态

Web UI 适合交互；自动化场景用 headless：

```bash
npx @deepseek-ai/dsh --profile headless "查看当前目录并列出文件"
```

一次性运行、打印最终答案、退出。它的会话仍然会被记录——日志是 harness 的"记忆"，本课程第 09-12 课会亲手实现。

## 5. 观察习惯

每次任务后用第 01 课的 `observation-template.md` 记录：请求原文、回复要点、工具调用表、token、疑问。这门课的价值不在"跑通"，而在"看明白每一步为什么发生"。

## 小结

- `dsh web` 是交互形态，`headless` 是自动化形态。
- 一个 turn = 一次用户输入到最终回答；一个 step = 一次模型请求 + 工具执行。
- 轨迹页是学习 harness 最好的教具：Turn/Step、工具卡片、消息来源、token。

## 预习

- 准备 3 个不同难度的任务（环境探测 / 文件读写 / 写一个小脚本）。
- 想想：如果让你自己实现「工具调用循环」，状态应该记在哪里？（第 05-06 课揭晓。）
